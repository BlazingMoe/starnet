# Decision: prove Moe's existing path before adding another runtime

Engineering recommendation, 2026-10-04. This document was prepared by Codex from the sources in sources.md, not generated by a live Moe run.

Keep StarNet/Moe as the foundation. Its existing dossier recipe and execution infrastructure make a baseline acceptance run the most direct next step. GPT Researcher is the first external research candidate to evaluate if that baseline exposes a concrete quality or capability gap. Borrow evaluation and research-stage ideas from Open Deep Research; its archived status weighs against a new operational dependency. Use Microsoft Agent Framework as an architectural reference rather than adding a second orchestrator.

The comparison is qualitative. No comparative latency, cost or quality measurements have been obtained. Licensing labels require inspection of the exact files and notices before any code port. No third-party implementation has been installed or imported by this research.

## Acceptance sequence

1. Plumbing: run the existing `test/harness.integration.test.js`. The added dossier scenario must search/fetch, write four files, read them back and reconstruct their evidence with a fresh journal instance. This deterministic fixture is now passing.
2. Live baseline: launch Moe in an isolated test workspace using a verified configured model and existing grants/budget. Run the actual decision-dossier recipe on a low-risk tool-selection question. Save sources.md, comparison.csv, decision.md and progress.md. Record run ID, model, tool results and observed spend; unavailable spend stays unknown.
3. Review: verify the sources support the decisive claims, apply the same criteria to each option, disclose unknowns and conflicting evidence, and check no mandatory constraint is ignored. Read-back proves persistence, not truth.
4. Restart acceptance: interrupt a read-only stage, reopen the same task and verify continuation preserves files and source evidence without duplicate external effects.
5. Compare a bounded external adapter only if the baseline fails a named criterion. Use the same question, review rubric and measured budget. Adopt it only after it demonstrably improves the result and preserves Moe's runtime boundaries.
