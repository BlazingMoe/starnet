GETTING STARTED

// from download to your first working agent

1. Download and install

The public release train targets Windows and macOS. Grab the right build from the releases page:

PlatformAsset
Windows 10 / 11 (64-bit)StarNet_<version>_x64-setup.exe
macOS — Apple Silicon (M1–M4)StarNet_<version>_aarch64.dmg
macOS — IntelStarNet_<version>_x64.dmg

Not sure which Mac you have? Apple menu → About This Mac. "Apple M…" means Apple Silicon; "Intel" means Intel. The wrong one won't run.

Windows first run

The public train requires a valid Authenticode publisher and trusted timestamp. SmartScreen can still show "Windows protected your PC" while a certificate builds reputation. Open More info, verify the publisher matches the release notes, and proceed only then.

macOS first run

  1. Open the .dmg and drag StarNet into Applications.
  2. Open StarNet from Applications. The public train requires Developer ID signing and a stapled Apple notarization ticket, so Gatekeeper should accept the release normally.

If Gatekeeper reports an unknown developer, missing notarization, or a damaged app, stop and report the release tag and asset name. Do not clear quarantine for a purported public release.

2. Connect a provider

On first launch StarNet asks for one model provider. An OpenRouter API key works everywhere (hundreds of models through one key), or use a supported OAuth sign-in. Details in Providers & keys.

3. Awaken your first agent

The onboarding flow walks you through recruiting your first crew member: a short interview shapes its dossier, it takes a desk in your station, and you give it its first task from the COMMS window. When it uses a real tool you'll see it move to the workstation that grants that tool — the animation is driven by the actual run, not a script.

4. Updates

The public train produces signed updater artifacts for Windows and both Mac architectures. The Update Center verifies downloads against a key baked into the app before installation, independently of OS signing. This is the supported path, not proof that a specific candidate was installed and updated; use the matching release installer if an update cannot complete.

Run from source

The sidecar runs on Node core modules alone — no npm install needed:

git clone https://github.com/androoAGI/starnet.git
cd starnet
node sidecar/index.js
# open http://localhost:8787

One exception: hands-free Live Voice needs the two offline speech packages (@huggingface/transformers and kokoro-js). The desktop installers ship them, so downloaded builds need nothing extra — but a from-source checkout has to install them before Live Voice will start:

npm install

Without them the station still runs normally. On Windows, Live Voice can fall back to the operating system's offline dictation engine and keyless Edge speech; on other platforms the panel refuses before opening your microphone because it has no local listening engine.
